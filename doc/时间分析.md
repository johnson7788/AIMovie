  最大优化机会

  1. 并行化 Shot 间 LLM 提示词构建（~3m21s，难度低）
  目前每个 shot 的视频生成完成后，才开始构建下一个 shot 的图片提示词。这个 LLM 调用（43-60s）完全可以在上一个 视频生成等待期间
  并行进行，提前生成好，视频一完成就立即开始图片生成。

  2. 流水线：上一个 shot 视频生成期间就开始下一个 shot 图片生成（~4m14s，难度中）
  当前流程完全串行：image₀→video₀→image₁→video₁。连续帧的约束（需要上一 shot 的 last_frame）是瓶颈，但可以用 上上 shot 的 last_frame 作为占位符
  先生成图，video 完成后再做一次 continuity check 重试（如果 MSE 太高）。

  3. Shot 2 的 retry 耗时 43s（难度低）
  LLM 输出了拼写错误 "meduim" 导致解析失败，重试。加一个 fuzzy 匹配或枚举规范化（medium/meduim/MEDIUM → medium）即可消除这类 retry。

  4. 视频生成时间不稳定（Shot4 耗 208s vs Shot1 耗 106s）
  这是上游 Seedance API 的问题，可以考虑如果超时（如超过 150s）就 cancel 并重新提交。

  理论上通过 1+2 优化，可以把总耗时从 25min 压缩到接近视频生成的串行极限（约 12-13min，减少约 50%）。
